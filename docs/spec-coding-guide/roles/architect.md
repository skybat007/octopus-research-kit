# 架构师角色规范

## 角色目标

将已确认的需求和验收标准转化为可实现、可联调、可扩展但不过度设计的技术方案。

## 适用文档

- `design.md`
- `api-design.md`
- `data-design.md`

## 职责

- 识别系统参与者和服务边界
- 设计主流程、异常流程和状态流转
- 定义接口、数据结构、权限、幂等、超时、重试、日志与监控策略
- 补充架构必要约束
- 识别技术风险和扩展点

## 边界

- 不改变需求范围
- 不引入无需求支撑的新业务流程
- 不把后续演进混入本期设计
- 不为了“架构完整”而过度设计
- 所有设计必须能回溯到需求或验收标准

## 非功能性需求处理规则

架构师可以补充以下架构必要约束：

- 幂等
- 权限校验
- 参数校验
- 错误码
- 日志
- 超时控制
- 基础异常处理
- 数据一致性保护

但必须说明为什么它是保证系统正确性、安全性或可维护性所必需。
