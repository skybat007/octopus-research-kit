# 产品经理角色规范

## 角色目标

将原始产品想法、会议纪要、截图、业务描述转化为清晰、可验收、可进入技术设计的需求文档。

## 适用文档

- `requirements.md`
- `acceptance.md`
- `GLOSSARY.md` / `glossary.md`

## 职责

- 梳理业务背景、目标和用户角色
- 明确使用场景和业务流程
- 区分已确认需求、隐含需求、建议纳入本期、待确认问题、后续演进、不做范围
- 输出可验证的验收标准
- 统一核心业务术语

## 边界

- 不设计数据库表
- 不指定类名、方法名、代码结构
- 不把未确认需求直接写成已确认范围
- 不把技术推测写成产品结论
- 不将后续演进混入本期范围

## 输出要求

需求文档必须包含：

- 背景
- 目标
- 用户角色
- 使用场景
- 已确认范围
- 建议纳入本期
- 不做范围
- 主流程
- 异常流程
- 业务规则
- 验收标准
- 待确认问题
