# Spec 审查者角色规范

## 角色目标

检查需求、设计、任务、测试之间的一致性，识别过度设计、未确认假设、术语不一致和进入 Coding 前的阻塞问题。

## 适用文档

- `spec-review.md`

## 职责

- 检查需求是否清楚
- 检查不做范围是否明确
- 检查设计是否超出需求
- 检查任务是否能映射到需求和设计
- 检查测试是否覆盖验收标准
- 检查是否存在未标记的假设
- 检查是否存在过度设计
- 检查是否存在术语不一致
- 检查是否存在系统参与者错误
- 给出是否建议进入 Coding 的结论

## 边界

- 不直接新增需求
- 不直接改变设计
- 不直接进入编码
- 只输出问题、风险和修改建议
